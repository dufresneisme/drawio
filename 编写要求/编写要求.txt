CH32 充电控制盒工程编写要求

文档用途
- 本文件记录本项目在工程结构、硬件适配、代码实现、通信兼容、调度和文档交付方面已经明确的编写要求。
- 后续新增要求应继续追加或修订本文件；已经确认的要求与仍待原理图、芯片手册或实测确认的事项分开记录。
- 当前主工程为 CCB/ChargeControlBox，旧版 ChargeControllerBox 只作为协议、配置和保护策略的参考，不得未经明确要求直接修改旧工程。

一、工程范围与目标芯片

1.1 目标芯片
- 最终目标主控为 CH32V103R8T6，当前只按单芯片方案规划，不按双芯片方案设计。
- V303 仅作为早期临时验证方案；V103 板子到位后以 V103 为主，后续不再为 V303 保留独立架构。
- 当前时钟设计基准暂定为 72 MHz；最终须以 V103 工程启动代码、时钟树和实测配置为准。
- 新版硬件采用 CN3889 充电控制芯片和 BM3451 BMS，MCU 不负责产生充电 PWM。
- 后续可能增加 EEPROM、参数存储、SOE、板载温度和电池温度等功能，模块和配置结构应预留扩展能力。

1.2 工程文件和目录
- Firmware 可以放在 CH32 工程目录同级，通过 IDE 的“添加外部链接目录”链接到工程。
- Firmware 采用外部链接方式时，不要再把同一批源文件重复复制到工程内部，避免重复编译和路径混乱。
- 工程中应区分源代码目录、构建输出目录和 IDE 工程目录；obj、Debug 等生成目录不应被当成源码目录。
- `.wvproj` 工程文件必须保留并纳入工程管理，不能因为是 IDE 文件而忽略。
- 头文件路径应添加到 C 编译器的 Include paths；汇编器只保留 Startup 汇编确实需要的路径，避免把全部 C 头文件路径加入汇编器。
- 当前工程目录中 Firmware 的 App、Common、Config、Drivers、Module 等目录应保持清晰，不通过临时复制制造第二套实现。

二、软件分层与依赖方向

2.1 分层职责
- App 层：放置面向业务的高级任务和流程，例如周期测量、周期保护检查、周期扫描、状态机和应用调度。
- Module 层：放置功能模块接口及其实现，提供给 App 调用，并向下调用 BSP 或驱动接口。
- BSP 层：只负责主控和板级硬件抽象，例如 ADC、DMA、UART、RTC、定时器、GPIO 和 Flash。
- Drivers/Peripheral 层：放置芯片库、外设底层驱动或厂商库封装。
- Config 层：放置默认参数、参数校验、Flash/EEPROM 存储和运行时配置管理。
- Common 层：放置协议编解码、CRC、通用数据类型和不依赖具体业务的公共工具。

2.2 依赖规则
- 依赖方向应保持为 App -> Module -> BSP/Drivers，底层不得反向调用上层业务函数。
- BSP 不得调用 App 或 Module 的业务接口；协议编解码层不得直接操作 UART、DMA 或 BSP 寄存器。
- 需要跨层通知时，使用接口、事件、状态或回调，并明确所有权，不能通过隐式全局调用形成环依赖。
- 一个模块的头文件只暴露必要的公共接口；内部辅助函数尽量使用 static，避免污染全局命名空间。
- `measurement` 是测量模块的正式名称；原 `charger_manager` 应重命名为 `measurement`，重命名之前删除旧的同名 measurement 实现，避免同名文件并存。

三、硬件引脚和采集要求

3.1 当前 ADC 通道
- PC0 / ADC10：太阳能电压采样。
- PC1 / ADC11：充电电流 1。
- PC2 / ADC12：充电电流 2；原理图中 PC3 的标注属于错误，程序按 PC2 处理。
- PA4 / ADC4：工作电压。
- PA5 / ADC5：放电电流采样，优先级最高。
- PA6 / ADC6：板载温度。
- PA7 / ADC7：MOS 管温度。
- PC4 / ADC14：电池电压；此前标注为其他引脚属于错误，程序按 PC4 处理。

3.2 ADC 和快速保护
- 放电电流保护要求采样间隔不大于 100 us；短路保护目标处理级别为约 50~200 us。
- 放电电流是快速保护专用数据源，不能因为普通 7 路扫描而延迟保护判断。
- 可考虑放电电流单独 ADC DMA，或使用 ADC 注入组；最终方案必须确认 ADC 触发源、DMA/注入资源、数据覆盖关系、中断优先级和对普通规则组的影响。
- 普通 7 路 ADC 扫描用于电压、充电电流和温度等测量；保护原始数据与上报/显示数据可以分开处理。
- 快速保护使用原始采样或低延迟数据；电流上报可以采用多次采样、累计平均或滤波，不能用慢速滤波结果替代快速保护判断。
- ADC 采样时间、转换时间、ADC 时钟和一轮扫描时间必须按芯片手册计算后确定，不能只凭“频率越高越好”决定。
- 原始 ADC 值与物理量换算必须集中在测量模块，保护模块明确使用原始阈值还是换算后的物理阈值。
- 电池电压目前按“ADC 测得电压 × 5 + 补偿值”换算；补偿初始约为 10~11 mV，最终数值以标定结果为准，并应设计为可配置参数。

3.3 未使用的外设资源
- MCU 不需要产生充电 PWM，PWM 由 CN3889 产生。
- 当前不需要输入捕获功能。
- TIM3/TIM4 的最终用途必须结合 ADC 触发、DMA、引脚复用和其他外设资源确认，不能只按定时器编号直接定案。
- WDI_INPUT 当前可能未连接到 MCU；未确认前不能编写依赖该输入的功能。

四、通信要求

4.1 物理串口
- PA9/PA10 用于上位机网关通信，必须采用非阻塞收发，使用 DMA 配合中断或状态机完成接收和发送。
- 网关通信默认波特率为 9600，允许通过配置改为 115200，也应保留旧上位机支持的波特率映射。
- PA2/PA3 用于调试串口，允许阻塞式收发，默认波特率为 115200。
- 网关通信不能使用 printf 或单字节轮询发送作为正常业务通道；调试串口与网关串口职责分离。

4.2 通信软件结构
- UART/DMA 接收层负责收集字节、识别一帧完成并把完整帧提交给协议层。
- 协议层只负责帧格式、地址、功能码、CRC、字段映射和业务接口调用，不直接访问 UART、DMA 或寄存器。
- 发送必须通过异步发送队列或发送状态机完成，不能在协议处理函数中等待整个帧发送结束。
- 兼容旧上位机的 QL 协议优先实现，后续再接入 HY 协议；旧字段应保留。
- 上位机协议配置字段应沿用旧工程结构，保证新板能直接与旧上位机通信。
- 需要明确旧协议字段是物理派生值、缩放值还是 ADC 原始值；配置和实时量的缩放、符号、字节序必须在协议映射表中固定。
- 电池温度字段暂时保留，即使当前没有实际接口，上报值按 25 ℃ 处理，并在注释中说明这是兼容占位值。

五、任务调度和时间基准

5.1 时间基准
- 调度基准由定时器中断产生；定时器中断只做置位节拍标志、计数和必要的快速保护触发，不执行耗时业务。
- TIM2 可作为系统基础节拍及 5 倍、10 倍、100 倍、1000 倍周期的时间基准；具体频率和分频需结合最终时钟配置确认。
- 快速保护可由 TIM3 或 TIM4 提供周期触发，但最终定时器必须结合 ADC 触发和资源复用确认。
- 不应依赖 while 循环自身提供精确周期；`APP_Run()` 应在主循环中反复调用，根据定时器产生的标志运行到期任务。
- `APP_Run()` 不是只执行一次后内部自动精确循环；精确的时间到期由定时器节拍和任务标志保证。

5.2 调度方式
- 当前采用静态任务表 + 主循环轮询的裸机时间片方式，任务表应包含任务函数、周期、偏移量、任务索引、启用状态等信息。
- 三个基础任务需要明确填入偏移量，避免上电时所有任务同一时刻集中执行。
- 每个任务必须预估执行时间，禁止在任务中使用长时间阻塞延时、无限等待或阻塞式通信。
- 超时机制可以用于监控任务执行时间、记录异常或跳过过期任务，但不能把主循环抢占式调度误认为已经实现；真正的快速保护仍应由定时器/ADC路径保证。
- 普通测量、状态刷新、协议处理和参数保存等任务应放在主循环或低优先级任务中；50~200 us 保护路径不得依赖主循环及时轮询。
- `APP_Run()` 中不能保留临时软件节拍；应统一调用已经封装好的 BSP 定时器/节拍接口。

六、保护和配置要求

6.1 放电电流保护
- 放电电流保护沿用旧工程的三段式方案。
- 第一段、第二段和第三段的阈值、延时、限幅及重试参数应配置化，不能散落在业务代码中。
- 放电采样电阻为 1 mΩ，满量程约 66 A；当前保护设计暂以 60 A 对应的原始值作为一项初始保护目标，实际阈值必须结合 ADC 标定确认。
- 第二段保护保留 I-t 参数。
- 第三段默认阈值按 5 A 处理，代码注释也必须写 5 A，不能沿用旧版过时注释。
- 快速短路判断、毫秒级过流判断和更慢的重试/稳定清除应分层处理，不能全部塞进一个周期任务。

6.2 配置加载、校验和保存
- 上电后优先读取 Flash 中保存的配置；配置不存在、校验失败、版本不兼容或越界时，使用程序内默认配置。
- 配置结构要保留旧字段，以兼容旧上位机和后续扩展。
- `DSG_SaveConfigToFlash()` 必须改为后台非阻塞保存，不能在通信接收或保护路径中长时间阻塞。
- 配置写入流程应采用“协议解码到候选副本 -> 整体校验 -> 提交运行配置 -> 后台保存”的顺序，避免半组参数生效。
- Flash/EEPROM 存储接口属于 BSP/Config 层，不应由 App 或协议底层直接操作寄存器。
- 后续 EEPROM、SOE、温度传感器等功能加入时，应复用统一配置版本、校验和、默认值及升级策略。

七、代码编写规范

7.1 格式和编码
- 全工程保持 UTF-8 编码；新增和修改的中文注释不能使用本地代码页编码。
- 所有条件、循环、函数和结构体的大括号，左大括号单独另起一行，不放在条件或函数声明右侧。
- 命名应体现模块归属和职责，避免使用含义不清的全局变量和缩写。
- 保持已有工程风格，不进行与当前任务无关的大规模格式化。

7.2 注释要求
- 对改动过的代码添加详略得当的中文注释，重点解释协议格式、单位换算、时序约束、硬件限制和兼容性原因。
- 每个对外函数和重要静态函数的函数头前应有注释，至少包含 `@brief`、`@param`、`@return`；必要时补充 `@note`。
- 注释必须描述真实行为，不能把暂定值写成已经验证的最终值。
- 对兼容旧协议的字段、暂未接入的硬件、默认占位值和未实现寄存器应明确标注原因。
- 注释不要重复代码表面动作，应优先说明为什么这样做、单位是什么、失败如何处理以及后续更换硬件时要改哪里。

7.3 阻塞与非阻塞
- 网关串口收发、Flash 参数保存和快速保护相关路径必须非阻塞。
- 调试串口允许阻塞式输出，但不能让调试输出影响保护、测量和网关通信。
- `printf` 只能用于调试或明确允许的低优先级场景，不能放入高频保护中断和 DMA 回调。
- 底层驱动接口应返回状态或通过事件通知完成，不能用长延时等待硬件完成。

八、开发顺序和替换策略

8.1 板子到位前可先完成
- 文件目录、分层接口、数据结构、默认配置、参数校验、协议编解码、CRC、任务调度框架和不依赖实物的测量换算可以先写。
- 可以先完成 BSP 定时器接口、ADC/DMA 数据结构和保护状态机，但必须把芯片寄存器、DMA 通道、引脚复用等待确认项集中标注。
- 可以先完成 QL 兼容协议和后台保存状态机，但 Flash/EEPROM 地址、擦写粒度和实际通信时序需在板上验证。

8.2 V103 板子到位后优先确认
- 主频、时钟树、ADC 时钟、采样时间和实际转换时间。
- ADC 规则组/注入组或独立 DMA 的最终选择、触发定时器、DMA 通道和中断优先级。
- TIM2、TIM3、TIM4 是否与 ADC 触发、PWM、输入捕获或引脚复用冲突。
- PA9/PA10 网关 DMA 收发、PA2/PA3 调试串口的实际引脚复用和波特率切换。
- 1 mΩ 放电电流通道的零点、满量程、60 A 初始保护原始值及滤波/标定参数。
- CN3889、BM3451、温度传感器、EEPROM 和 WDI_INPUT 的实际连接情况。

8.3 旧工程的使用边界
- 旧版工程只用于参考：三段式保护、配置字段、Flash 数据格式和旧上位机协议。
- 复制旧代码前必须重新确认其阻塞性、单位、原始值/物理值含义和硬件引脚，不得直接假设可以复用。
- 新 CCB 工程的底层 BSP 应按 V103 实际资源重写或适配；上层接口尽量保持稳定，使板子到位后主要替换 BSP 和参数。

九、文档、检查与交付

9.1 文档
- 软件设计文档放在 `001WCHCCB/doc/软件设计文档`。
- 软件设计文档二级标题使用数字格式，例如 `12.1`，不要直接使用中文数字编号。
- 架构讨论、调度方式对比和框架决定记录在 `001WCHCCB/doc/大致框架` 下的 TXT 文档中，格式保持朴素易读。
- 本文件放在 `001WCHCCB/doc/编写要求`，作为后续实现和审查的约束清单。

9.2 检查与响应习惯
- 检查代码前先读取真实文件和工程配置，再判断是否已经完成，不凭截图或推测宣称完成。
- 用户要求“简短回答”时只给结论和必要依据；需要设计分析或计算时再展开过程。
- 用户要求“不做对比”时只检查目标范围；旧工程仅在明确要求兼容时作为参考。
- 用户暂时要求不编译时，可以先完成代码和静态检查，但应明确说明尚未执行编译验证。
- 修改后至少检查 UTF-8 编码、括号格式、路径引用、重复源文件、关键接口依赖和 Git 差异；涉及硬件时列出仍需板上确认的项目。

十、当前明确的未定事项

以下内容不能在没有最终硬件资料或实测数据时擅自定案：
- TIM3/TIM4 的最终分工以及是否由 TIM2 统一累计所有低速节拍。
- ADC 规则组与放电电流独立 DMA/注入组的最终实现方式。
- ADC 采样时间、转换时间、ADC 时钟和一轮 8 路或 7 路采样的精确计算结果。
- V103 实际 DMA 通道、定时器触发映射、GPIO 复用和 UART DMA 资源。
- 电池电压补偿值的最终标定结果，以及放电电流 60 A 对应原始值。
- 新版原理图中 EEPROM、温度传感器、WDI_INPUT 和其他可能改动的连接。
- HY 协议字段和旧上位机尚未覆盖的兼容细节。
